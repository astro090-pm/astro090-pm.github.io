# Продуктовый кейс

Превращает разрозненные материалы о проекте в кейс, который нанимающий менеджер прочитает за две минуты и поймёт, как продакт думал.

## Шаг 1. Собери факты, ничего не придумывая

Прочитай всё, что дал пользователь (резюме, презентации, отчёты, ссылки). Выпиши в черновик:
- продукт, компания, роль, сроки, аудитория, стадия, стек;
- проблема и для кого она;
- что сделал сам продакт (глаголы первого лица: «провёл», «спроектировал», «запустил»);
- метрики до/после с единицами и периодом.

Если цифры нет в источниках — не придумывай. Оставь пометку и задай вопрос.

## Шаг 2. Задай недостающие вопросы

Сильному кейсу нужны ответы, которых обычно нет в резюме. Спроси коротко, списком:
1. Какие гипотезы были и как их проверяли?
2. Что не сработало и что из этого вынесли?
3. Какое решение было самым трудным — и какой компромисс приняли?
4. По какой метрике судили об успехе и почему по ней?

Если пользователь не ответил — пиши кейс без этих разделов, а не выдумывай их.

## Шаг 3. Напиши кейс по структуре

```
# <Продукт>: <суть одной фразой>

**<Роль>** · <Компания> · <период>

| | |
|---|---|
| **Продукт** | ... |
| **Аудитория** | ... |
| **Стадия** | ... |
| **Главный результат** | ... |

## Контекст / Проблема
## Что я сделал
## Гипотезы и решения        (только если есть ответы)
## Результаты                (таблица «метрика | изменение»)
## Что этот кейс показывает   (1–2 предложения: какой навык доказан)
```

## Правила

- Пиши от первого лица, коротко, глаголами действия.
- Одна мысль — один пункт. Без «успешно», «эффективно», «инновационный».
- Цифры жирным, с единицами: **+103%** выручки за 12 месяцев.
- Текущий работодатель — только то, что уже есть в публичном резюме. Никаких внутренних цифр, имён коллег и названий систем.
- Чужие имена, фото и контакты из презентаций не переносить.
- В конце перечисли пользователю, что взято из источников, а что требует проверки.
